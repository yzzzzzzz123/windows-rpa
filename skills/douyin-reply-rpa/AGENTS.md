# 抖音定向回复 Skill 维护约定

- 本目录只处理评论区候选发现和对指定原评论的回复。顶层视频留言属于 douyin-rpa；不得降级成顶层留言凑数。
- 唯一源码保存在项目 `skills/douyin-reply-rpa`。未经用户明确要求，不安装、复制、链接或注册到任何内部或全局 Skill 库。
- 当前会话 AI 执行语义筛选和自然回复写作；脚本不得把关键词命中伪装成 AI 判断，也不暗中接入外部模型。
- 推广对象为漫映，主要做免费动漫资源分享，资源丰富。采用宽容筛选：问哪里看、求番名、求推荐、想看想追、来源或播放困难均可，不要求明确免费需求，也不要求尚未被别人回答；逐条结合原评论改写回复并提到“漫映”，不猜片名、集数或库存。对外回复直接使用“漫映Manying”，不写“公众号”等入口标签，不冒充独立观众。
- 文案按 `references/reply-flow.md` 的写作要求执行：短句直接答，不复述提问、不套品牌介绍，不把同一句广告换词发；不能回答的具体问题不硬推。免费和资源多按需提，不要求每条同时出现。
- 先读 `SKILL.md`、`references/reply-flow.md`。按用户设定，定向回复默认直接 Publish 并持续处理，不再逐次请求发送授权或文案确认；未指定数量时没有累计上限，不能因发送 3 次或本轮候选耗尽而结束。用户明确要求持久目标时创建并保持系统目标 active，由当前 AI 持续编排。用户明确指定数量、指定批次、只发现或预演时按该范围处理；维护、测试和构建不启动真实发送。
- 定向回复按单视频 Discover（显式 MaxVideos=1）与一次一个回复的 Publish 编排。发送点击完成并记为 Submitted 后，从实际提交时间起等待 10 秒才寻找、打开或采集下一视频；相邻发送也至少间隔 10 秒，未成功不加业务停留。下一视频调度由当前 AI 执行，发送冷却由执行器根据共享时间账执行。保留暂停、停止、去重及未知提交，不把 Submitted 宣称为送达或实际转化成功。
- 保留 CommentId、VideoId、作者主页及原文的来源绑定；候选身份为 `SHA256(VideoId + '|' + CommentId)`，用户身份为 `SHA256(AuthorUrl)`。公开 UIA 的 `tooltip_<19位评论编号>` 是评论身份线索，实发前仍需重核当前目标。
- Publish 必须对唯一可见原评论进行作者、正文、评论编号、视频编号核验，确认回复收件人和空编辑器，再输入并回读。任何歧义都停止该次操作，不用坐标猜测，允许由会话 0 使用 Windows 任务计划程序的同账号 InteractiveToken 单次桥接到唯一活动用户会话；不提权、不保存密码，仍核验 Default 桌面已解锁。不得跳过验证码、桌面与目标核验。
- 评论与用户双维永久去重。先持久化提交声明和共享 Pending，再单次发送；Unknown、NeedsVisualReview、部分落账和任何历史提交均禁止自动重试。迁移必须保留账本与历史冷却。
- 与旧视频评论 Skill 共用 `data/douyin-rpa/state/runner.lock`、`last-submit.json` 和 `send-interval-start.json`；任务控制和回复账保存在本 Skill DataRoot/state。定向回复最短间隔 10 秒，首发也冷却；顶层评论保持自己的配置。持久目标在 `state/persistent-goal.json` 保存进度，接续保留已查看视频、已处理目标、当前 JobId 与下一视频允许时间。
- Submitted 仅代表发送动作执行过，不承诺可见或审核成功；发送后不自动刷新核验。Preview 仅定位与核验，不输入、不发送。
- 保留 PID 与启动时间身份校验、排他派发、任务专属控制、暂停心跳与停止不可恢复语义。控制旧任务不能影响新实例。
- PowerShell 使用 Windows PowerShell 5.1，`.ps1` 保存为 UTF-8 BOM；任务及结果 JSON 明确按 UTF-8 读写。测试临时文件限项目 `artifacts/work`，清理前验证绝对路径边界。
- 公共原生与浏览器能力维护于 `shared`，业务专属代码维护于本目录。离线测试不得控制真实桌面或发送评论。
