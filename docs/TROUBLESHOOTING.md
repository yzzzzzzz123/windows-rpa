# 故障排查

先看 `result.json` 的状态与原因，再看 `focus-history.json` 的阶段和前台窗口；需要确认页面时查看截图。不要只依据控制台中的「已点击」判断成功。

## 当前位于 Codex 隔离桌面

脚本在注入输入前主动停止。使用 Windows 桌面中的项目启动器运行。`-SelfTest` 可以在隔离桌面内完成，且不会操作应用。

## 未找到唯一钉钉主窗口

查看 `windows.json`。脚本只选择钉钉进程内标题为钉钉 / DingTalk 的主窗口，排除服务平台等业务窗口。窗口数为零时先检查桌面环境；有多个候选时不猜测目标。

## 前台窗口不属于钉钉 / 目标窗口失去焦点

查看焦点记录的 `Foreground`：包含句柄、进程名、可读取的程序路径、标题、窗口类名。

目前在导航完成后最多等待 6 秒。自动恢复仅针对无前台窗口，或启动时记录的同一经典控制台 `ConsoleWindowClass`，且只激活唯一可确认的钉钉目标。

最新记录的前台为 `WindowsTerminal / CASCADIA_HOSTING_WINDOW_CLASS`。这一类型当前不在恢复范围内；程序正常停止。不要简单移除焦点检查，因为后续鼠标输入可能落到终端或其他应用。焦点切换原因尚未确认。

## 无法唯一识别低代码平台

先用 UIA 查找精确名称，再用系统 OCR 的连续文字精确匹配。零个或多个匹配都会停止。查看 `01-app-center.png` 和 `app-center-controls.json`，确认页面是否加载、文案是否改变、是否存在多个同名入口。

OCR 依赖 Windows 用户语言的识别能力。如果系统没有 OCR 引擎，脚本会报错并停止。自检只检查编译和配置，不保证当前页面可被 OCR 正确识别。

## 已滚动但状态是 NeedsVisualReview

优先使用 UIA ScrollPattern 的滚动百分比；没有可用控件时使用有次数上限的鼠标滚轮。连续截图不变只用于停止重复滚动，不能证明已经到底。查看 `02-low-code-before-scroll.png` 与 `03-bottom.png`；页面有多个滚动区域时还需确认滚动的是内容区域。

## 退出码

`0` 为成功完成当前模式，`2` 为操作后待人工复核，`1` 为停止或失败。自检的 `0` 不代表钉钉流程完成。
