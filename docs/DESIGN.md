# 实现说明

## 执行链路

用户启动 `.cmd` → Windows PowerShell 5.1 → 配置校验与原生接口加载 → 识别桌面与钉钉主窗口 → 激活并截图 → 调用业务流程 → 保存结果与退出码。

所有路径由项目根目录计算，项目源码不依赖原聊天目录或桌面脚本。运行证据默认位于项目内，可以用参数改为其他可写目录。

## 定位策略

- 主窗口：可见的 DingTalk 进程窗口，加上明确标题约束。
- 应用中心：唯一 AutomationId、精确名称、Button 类型、可见且可用，并使用当前控件矩形点击。
- 低代码平台：UIA 精确名称优先，找不到时使用系统 OCR 精确文本；多个候选停止。
- 滚动区域：优先选择符合页面大小要求的 ScrollPattern 容器；否则在内容区域发送滚轮输入并保存截图。

## 结果证据

`windows.json` 保存桌面与目标窗口信息；`focus-history.json` 保存关键阶段焦点；`result.json` 保存已发送动作和验证状态；截图保存可见页面。上述资料默认不进入 Git。

`Passed` 必须同时有类别选中状态与到底的控件证据。OCR 点击通常没有 SelectionItemPattern，因此即便流程执行完也可能为 `NeedsVisualReview`。

## 扩展方式

新应用应新增工作流文件及明确的窗口定位规则，再由统一入口加入命名模式。不要让任意配置输入变成动态 PowerShell 代码，也不要扩大到所有同名进程或所有浏览器窗口。更改执行边界时需要对应的真实桌面验证。

当前还保留了基线中的系统菜单与导航状态辅助函数，供后续诊断复用。它们不会被默认流程调用。
